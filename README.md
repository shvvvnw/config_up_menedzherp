# Dependency Visualizer

Конфигурационное управление, вариант 7. Реализованы этапы 1–5.

## Запуск

```bash
python3 -m pip install -r requirements.txt
./run.sh
```

На macOS и Linux скрипт `run.sh` запускает Python из `.venv`, если она
создана, иначе использует `python3`. Его можно вызывать из любой папки.

Настройки читаются из `config.yaml` в корне проекта. Путь тестового
репозитория отсчитывается от папки конфигурации.

`src/main.py` запускает программу, `configuration.py` проверяет настройки,
`repository.py` получает данные, `graph.py` выполняет обход и ищет циклы,
`visualization.py` формирует D2 и ASCII-дерево.
Все этапы используют один запуск через `src/main.py`.

## Этап 3

Используется DFS со стеком без рекурсии. Глубина корня равна 0.
При `max_depth: 0` выводится только корень, при 1 — его прямые зависимости.
Узлы на предельной глубине включаются, но их зависимости не запрашиваются.
Циклы определяются в построенной части графа; обход на них не зацикливается.
Если узел найден по более короткому пути, он обрабатывается повторно.

Текущая конфигурация использует `test_rapo.yaml` с циклом A → B → D → A.
Чтобы продемонстрировать разные случаи, в `repository_url` можно указать:

| Файл | Ожидаемый результат при корне A и глубине 3 |
| --- | --- |
| `tests/fixtures/cycle.yaml` | Цикл A → B → D → A |
| `tests/fixtures/acyclic.yaml` | Общая зависимость D, циклов нет |
| `tests/fixtures/self_cycle.yaml` | Цикл A → A |
| `tests/fixtures/missing.yaml` | Ошибка: B не описан |

Для этих примеров нужен `test_mode: true`. В тестовом файле ключи — имена
пакетов из больших латинских букв, значения — списки зависимостей.
Каждая упомянутая зависимость должна иметь свой ключ.

## Проверки

```bash
python3 -B -m unittest discover -s tests -v
```

Проверяются транзитивность, глубины 0 и 1, циклы, общий узел на более
коротком пути, цепочка из 1501 узла, неверный тестовый репозиторий
и запуск CLI вне папки проекта.

## Режим PyPI

Для реальных пакетов установите `test_mode: false`, `package_name: requests`
и `repository_url: https://pypi.org/pypi`.
Данные загружаются стандартными средствами Python, без pip или сторонних
библиотек для получения зависимостей. PyYAML нужен только для чтения YAML.

Строится граф всех объявленных зависимостей, включая дополнительные
и условные. Условия окружения и ограничения версий не вычисляются;
поэтому граф может отличаться от результата установки pip.
Отсутствие циклов утверждается только для исследованной части графа.
При `ascii_tree: true` дополнительно выводится ASCII-дерево.

## Этап 4: порядок загрузки

Программа выводит зависимости перед использующими их пакетами.
Общая зависимость появляется в порядке только один раз. Независимые
пакеты могут иметь несколько допустимых взаимных порядков.
При цикле вместо некорректного порядка выводится сообщение о невозможности
его построения. Алгоритм работает со стеком, без рекурсии.

Если достигнута максимальная глубина, программа явно отмечает
неисследованные пакеты. В этом случае вывод относится только к построенной
части графа; полный порядок загрузки и отсутствие скрытых циклов не доказаны.

Текущий тестовый файл содержит цикл. Для примера успешного порядка укажите
в `config.yaml` значение `repository_url: tests/fixtures/acyclic.yaml`.
Ожидаемый порядок: `D -> B -> C -> A`.

Демонстрация шести случаев без изменения настроек:

```bash
python3 -B tests/demo_load_order.py
```

Результаты реальной установки pip в отдельную временную папку,
сравнение с программой и объяснение различий: [отчёт этапа 4](docs/stage4.md).

## Этап 5: визуализация

При запуске `python3 src/main.py` текст D2 выводится всегда.
Стрелка направлена от пакета к его зависимости. Имена пакетов используются
как подписи, а отдельные идентификаторы узлов предотвращают конфликты
с синтаксисом D2. Сохраняются отдельные узлы и циклические связи.

При `ascii_tree: true` выводится также дерево с ветками `|--` и `` `-- ``.
При `false` этот блок отсутствует. Метки:

- `[cycle]` — возврат к пакету в текущей ветке; обход ветки остановлен.
- `[seen]` — пакет уже показан с не меньшей доступной глубиной.
- `[depth limit]` — дальнейший анализ ограничен настройкой глубины.

Три примера, полученные с PyPI, включают D2, SVG-картинку, ASCII-дерево
и снимок графа в JSON:

- [requests](examples/stage5/requests.svg)
- [urllib3](examples/stage5/urllib3.svg)
- [six](examples/stage5/six.svg)

Повторить вывод примеров без интернета:

```bash
python3 -B examples/generate_visualizations.py --offline
```

Обновить примеры данными PyPI: та же команда без `--offline`.
Скрипт перезаписывает `.json`, `.d2` и `.txt` в `examples/stage5/`.
После обновления `.d2` изображения нужно заново скомпилировать установленным D2:

```bash
d2 examples/stage5/requests.d2 examples/stage5/requests.svg
d2 examples/stage5/urllib3.d2 examples/stage5/urllib3.svg
d2 examples/stage5/six.d2 examples/stage5/six.svg
```

D2 нужен только для превращения текста в картинку. Для запуска программы,
вывода текста D2 и ASCII-дерева устанавливать его не обязательно.
В примерах задана глубина 1; пунктирные узлы не исследовались дальше.
