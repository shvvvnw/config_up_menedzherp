# Этап 4: порядок загрузки зависимостей

Проверено 26 октября 2026 года. Python 3.9.6, pip 21.2.4.

## Реализация

`dependency_load_order()` в `src/graph.py` выполняет итеративный DFS.
Пакет добавляется в результат после завершения обработки всех его зависимостей.
Цвета узлов позволяют исключить повторы и обнаружить циклы. Возвращаться
к рекурсивным вызовам не требуется даже для длинных цепочек.

`src/main.py` выводит порядок при отсутствии циклов. Если построение
ограничено глубиной, выводится список неисследованных узлов и предупреждение,
что порядок относится только к построенной части графа. При цикле ни один
частичный результат не выдаётся за корректный полный порядок.

## Тестовые репозитории

Команда: `python3 -B tests/demo_load_order.py`.

| Случай | Глубина | Полученный результат |
| --- | --- | --- |
| A → B → C | 3 | C → B → A |
| A → B,C; B → D; C → D | 3 | D → B → C → A; D выведен один раз |
| A без зависимостей | 3 | A |
| A → B,C; B,C → D; D → A | 3 | Сообщение о цикле A → B → D → A |
| A → A | 3 | Сообщение о цикле A → A |
| A → B → C | 1 | B → A; предупреждение о неисследованном B |

Полный набор: `python3 -B -m unittest discover -s tests -v`.
Результат: 21 тест, OK. Среди проверок — цепочка из 1501 узла, общий пакет,
повторное достижение узла более коротким путём, ошибочная ссылка,
предупреждение о скрытом цикле за границей глубины и прерванный ответ сервера.

## Сравнение с настоящим pip

pip используется исключительно как внешний эталон для сравнения.
Программа получает зависимости из PyPI стандартной библиотекой Python.
Никакой код приложения не вызывает pip и не читает зависимости из его вывода.

Выполнены установки в две отдельные подпапки временного каталога
`/tmp/config-up-stage4.yZgKaj`. Окружение проекта не изменялось.
Команды (в активном окружении проекта):

```bash
python3 -m pip install --target /tmp/config-up-stage4.yZgKaj/requests --ignore-installed --only-binary=:all: --no-compile --no-cache-dir --disable-pip-version-check --no-input requests
python3 -m pip install --target /tmp/config-up-stage4.yZgKaj/six --ignore-installed --only-binary=:all: --no-compile --no-cache-dir --disable-pip-version-check --no-input six
```

При повторении следует выбрать новые пустые временные папки.
Порядок взят из строки `Installing collected packages`, а не из
порядка скачивания или итогового алфавитного списка версий.

### requests

Программа с корнем `requests` и `max_depth: 1` получила:

```text
charset-normalizer -> idna -> urllib3 -> certifi -> pysocks -> chardet -> requests
```

Это порядок построенной части графа. Шесть зависимостей находятся на
предельной глубине, поэтому их собственные зависимости не запрашивались.

Фактический вывод pip:

```text
Installing collected packages: urllib3, idna, charset-normalizer, certifi, requests
Successfully installed certifi-2026.10.23 charset-normalizer-3.5.2 idna-3.20 requests-2.32.5 urllib3-2.6.3
```

Причины различий:

1. Программа строит граф всех объявленных зависимостей. `pysocks` относится
   к `extra == "socks"`, `chardet` — к `extra == "use-chardet-on-py3"`.
   В команде pip эти возможности не включались, поэтому их установка не нужна.
2. Программа читала последнюю версию requests 2.34.2 с требованием Python >=3.10.
   В используемом Python 3.9.6 pip выбрал совместимую requests 2.32.5,
   у которой требование Python >=3.9. Оба требования сверены через
   `/pypi/requests/2.34.2/json` и `/pypi/requests/2.32.5/json`.
3. Порядок независимых зависимостей может различаться. В обоих результатах
   общие зависимости стоят перед requests, что соответствует направлению связей.
4. Граф программы ограничен глубиной и не разрешает ограничения версий
   или маркеры окружения. Он не является полным планом установки pip.

### six

Программа с корнем `six` и глубиной 2 получила полный граф `six: []`
и порядок `six`; неисследованных узлов нет.

Фактический вывод pip:

```text
Installing collected packages: six
Successfully installed six-1.17.0
```

Для этого пакета результаты совпали: дополнительных зависимостей нет.

## Ограничения

Для фиксированного ациклического графа вычисляется корректный порядок:
каждая зависимость предшествует своему потребителю. При сравнении с pip
нужно учитывать, что он выбирает совместимые версии и применяет условия
окружения. Приложение пока работает с графом всех объявленных связей.
Графические представления D2 и ASCII относятся к этапу 5.
